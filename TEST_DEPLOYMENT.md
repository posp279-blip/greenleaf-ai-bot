# Greenleaf AI Bot v2 — тестовый запуск

Тестовая ветка: `test/telegram-v2`

Цель: пройти новый Telegram-сценарий в полностью изолированной среде, не меняя основной Replit, основной Telegram-бот и рабочую базу данных.

## 1. Создать отдельного Telegram-бота

В BotFather:

1. Выполнить `/newbot`.
2. Название: `Greenleaf AI Bot v2 Test`.
3. Username должен заканчиваться на `bot`, например `greenleaf_ai_v2_test_bot`.
4. Сохранить выданный токен только в Replit Secrets под ключом `TELEGRAM_BOT_TOKEN`.
5. Не подставлять токен основного бота.

## 2. Создать отдельный Replit App

1. Создать новый проект, не изменяя рабочий Replit.
2. Подключить GitHub-репозиторий `posp279-blip/greenleaf-ai-bot`.
3. Выбрать ветку `test/telegram-v2`.
4. Убедиться, что проект не использует рабочий домен `greenleaf-ai-bot.replit.app`.
5. Не публиковать тестовую копию поверх существующего Deployment.

## 3. Создать отдельную базу данных

Нужна новая пустая PostgreSQL-база.

Запрещено использовать рабочий `DATABASE_URL`, потому что тесты создают сессии, сообщения, заявки, партнёров и AI-логи.

## 4. Добавить Replit Secrets

Использовать `.env.test.example` как перечень ключей.

Обязательные секреты:

- `DATABASE_URL` — отдельная тестовая база;
- `TELEGRAM_BOT_TOKEN` — токен нового тестового бота;
- `PROXY_API_KEY` — ключ Proxy API;
- `ADMIN_PASSWORD` — отдельный пароль тестовой админки;
- `SESSION_SECRET` — длинная случайная строка;
- `ADMIN_TELEGRAM_IDS` — числовой Telegram ID администратора.

Не задавать рабочий `REPLIT_APP_URL`. Приложение должно взять собственный домен тестовой копии.

## 5. Первый запуск

После старта проверить логи:

- база и seed проходят без ошибок;
- определяется username нового Telegram-бота;
- webhook установлен на домен тестового Replit;
- нет обращений к рабочему домену;
- Proxy API показывает доступность или корректный fallback.

## 6. Ручной тест сценария

Пройти минимум следующие варианты:

### Основной путь

1. `/start`.
2. Нажать «Начать».
3. Назвать имя.
4. Пройти все четыре категории.
5. Посмотреть и пропустить видео в разных категориях.
6. Ввести состав семьи.
7. Открыть расчёт.
8. Пройти компанию, условия, старт и модель «3 по 3».
9. Подтвердить финальный интерес.
10. Отправить контакт.
11. Проверить создание одной заявки.

### Альтернативные ответы

- отказаться называть имя;
- написать неизвестный бренд;
- написать «не пользуюсь»;
- задать вопрос в середине сценария;
- спросить о заработке;
- написать «дорого»;
- написать «это пирамида»;
- попросить регистрацию слишком рано;
- отправить короткое случайное сообщение;
- несколько раз нажать кнопку финальной заявки;
- отправить два сообщения подряд;
- перезапустить сценарий через меню.

### Реферальная проверка

1. Создать тестового партнёра.
2. Открыть бота по ссылке с активным `refCode`.
3. Создать заявку и проверить её привязку.
4. Повторить с ошибочным и неактивным `refCode` — привязка создаваться не должна.

### Админка

- вход с правильным паролем;
- блокировка после пяти неверных попыток;
- просмотр диалогов и заявок;
- изменение текста v2 в `scenario_blocks`;
- изменение видео;
- изменение калькулятора;
- проверка Telegram admin callbacks с неадминистративного аккаунта.

## 7. Критерии допуска к основному боту

Перенос в `main` разрешён только когда:

- весь основной маршрут пройден без тупиков;
- один ввод пользователя создаёт только один переход;
- видео не вызывают автоматического перескока;
- вопрос AI возвращает пользователя на прежний этап;
- повторная заявка не создаётся;
- refCode работает только для активного партнёра;
- основной Replit, бот и база не затронуты;
- CI ветки остаётся зелёным.

## Открытый вопрос калькулятора

Итоговые цифры документов расходятся с суммой строк на 1 000 ₽. До подтверждения тестируем фактическое суммирование активных строк базы без ручной подгонки.
